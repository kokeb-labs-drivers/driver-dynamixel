Detailed Description

The packet layer of DYNAMIXEL protocols 1.0 and 2.0: CRC-16, checksum, byte stuffing, the frame writer, the receive scanner and register value coding. Pure functions, no I/O.

Copyright
Copyright (c) 2026 The driver-dynamixel authors. SPDX-License-Identifier: MIT

Protocol 2.0 packet: FF FF FD 00 | ID | LEN_L LEN_H | INST | PARAM... | CRC_L CRC_H; LEN counts the instruction, the parameters and the CRC; a status packet carries the error byte as its first parameter. Byte stuffing inserts FD after every FF FF FD of the parameters (e-Manual, protocol 2.0, "Packet Process"). CRC-16 is polynomial 0x8005, initial value 0, no reflection (e-Manual, "CRC Calculation"), computed over the stuffed packet from the header to the last parameter. Protocol 1.0 packet: FF FF | ID | LEN | INST | PARAM... | CHK, LEN = parameters + 2, CHK = ~(ID + LEN + INST + PARAM...) (e-Manual, protocol 1.0).

◆ Scan()

constexpr ScanResult dynamixel::protocol::Scan ( Protocol  protocol,
std::span< const uint8_t >  bytes,
std::size_t  max_frame 
)
constexprnoexcept

Find the first valid status packet in received bytes, skipping garbage and resynchronising after a damaged packet.

A candidate is a header followed by an in-range length; it is valid when it fits max_frame, its instruction byte is the status instruction (protocol 2.0) and its CRC or checksum matches. A damaged candidate is dropped by one byte and the search continues inside it, so a real packet that starts within the damaged bytes is still found.

Parameters
protocolThe packet format.
bytesWhat the port returned so far.
max_frameThe largest packet the receive buffer holds.
Returns
The result; see ScanResult.
